# Java Persistence API
**The JPA Specification (Jakarta Persistence API) is a standard contract that defines how Domain Objects map to relational database tables, ensuring consistency across different ORM providers like Hibernate. It is not an implementation itself, but a rulebook that frameworks must follow.**  

ORM = **Object Relational Mapping**

It maps **Java Objects ↔ Database Tables**

| Java             | Database    |
| ---------------- | ----------- |
| Class            | Table       |
| Object           | Row         |
| Field            | Column      |
| Object Reference | Foreign Key |

Example:

```java
Connection conn = DriverManager.getConnection(url);

PreparedStatement stmt =
conn.prepareStatement("SELECT * FROM users WHERE id = ?");

stmt.setInt(1, 10);

ResultSet rs = stmt.executeQuery();

User user = new User();
user.setId(rs.getInt("id"));
user.setName(rs.getString("name"));
```

Problems:

* Too much **boilerplate code**
* Manual **object mapping**
* Hard to maintain
* Hard to manage relationships
  
## Java/Jakarta Persistence API

### Java Persistence API
 - Originally introduced as part of Java EE 5 (2006).
 - Standardized object-relational mapping (ORM) for Java.
 - Defined annotations (@Entity, @Table, @Id) and interfaces (EntityManager, Query).

## Jakarta Persistence API
 - After Oracle donated Java EE to the Eclipse Foundation, the namespace changed from javax.persistence → jakarta.persistence.
 - Functionally the same specification, but under the Jakarta EE umbrella.
 - Current versions evolve under Jakarta branding, ensuring future compatibility and updates.

## What JPA Specification Defines
- **Entity Mapping**  
  - Classes annotated with `@Entity` map to database tables.  
  - Fields/properties map to columns (`@Column`, `@Id`, etc.).  
    ```java
    import jakarta.persistence.Entity;
    import jakarta.persistence.Id;
    import jakarta.persistence.Column;
    
    @Entity
    public class Employee {
    
        @Id
        private Long id;   // Primary Key
    
        @Column(name = "emp_name", nullable = false, length = 100)
        private String name;  // Column with constraints
    
        @Column(unique = true)
        private String email; // Unique column
    
        private double salary; // Default column mapping
    }
    ```
    | Annotation | Purpose |
    | --- | --- |
    | **[@Entity](ca://s?q=JPA_Entity_annotation)** | Declares class as a persistent entity |
    | **[@Table](ca://s?q=JPA_Table_annotation)** | Customize table name/schema |
    | **[@Id](ca://s?q=JPA_Id_annotation)** | Primary key |
    | **[@GeneratedValue](ca://s?q=JPA_GeneratedValue_annotation)** | Auto-generate PK values |
    | **[@Column](ca://s?q=JPA_Column_annotation)** | Customize column mapping |
    | **[@Transient](ca://s?q=JPA_Transient_annotation)** | Excludes field from persistence |

    | Strategy | DB Support | Behavior |
    | --- | --- | --- |
    | **[AUTO](ca://s?q=JPA_GeneratedValue_AUTO)** | Universal | Delegates to provider → dialect decides |
    | **[IDENTITY](ca://s?q=JPA_GeneratedValue_IDENTITY)** | MySQL, SQL Server | Auto‑increment PK |
    | **[SEQUENCE](ca://s?q=JPA_GeneratedValue_SEQUENCE)** | Oracle, PostgreSQL | Uses sequence objects |
    | **[TABLE](ca://s?q=JPA_GeneratedValue_TABLE)** | Any DB | Uses a special table to generate IDs |

- **Relationships**  
  - Rules for `@OneToOne`, `@OneToMany`, `@ManyToMany`, and `@ManyToOne`.  
  - Defines ownership and cascading behaviors.
  - @OneToOne
     - Each entity has exactly one related entity.
     - Ownership defined by mappedBy (the side with mappedBy is non‑owning).
     - Cascade often used for dependent objects.
     ```java
       @Entity
       public class Passport {
           @Id @GeneratedValue
           private Long id;
       
           @OneToOne(mappedBy = "passport", cascade = CascadeType.ALL)
           private Person person;
       }
       
       @Entity
       public class Person {
           @Id @GeneratedValue
           private Long id;
       
           @OneToOne
           private Passport passport;
       }
     ```
     In your case:
      - Person has the passport field → Owning side (foreign key passport_id in Person table).
      - Passport has the person field with mappedBy = "passport" → Inverse side (no foreign key here, just a mirror).

  - @OneToMany
     - One entity relates to many others.   
     - Typically combined with @ManyToOne on the child side.    
     - Ownership: the child (@ManyToOne) holds the foreign key.
    
  - @ManyToOne
     - Many entities reference one parent.
     - The owning side — foreign key column resides here.
     - Cascade usually not applied (to avoid deleting parent when child is removed).
    
    @ManyToMany
     - Many entities relate to many others.
     - Requires a join table.
     - Ownership defined by mappedBy.

- **Persistence Context**  
  - Managed by `EntityManager`.  
  - Ensures identity and lifecycle of entities (persist, merge, remove, detach).  

- **Query Language**  
  - JPQL (Java Persistence Query Language) is part of the spec.  
  - Abstracts SQL into object-oriented queries.  

- **Transactions**  
  - Defines how persistence contexts synchronize with database transactions.  

- **Inheritance Strategies**  
  - Single table, joined, or table-per-class mappings.  


## Quick Comparison
| Layer | Role | Example |
|-------|------|---------|
| **JPA Specification** | Rulebook | Defines `@Entity`, `EntityManager`, JPQL |
| **Hibernate** | Implementation | Provides ORM engine, SQL generation |
| **Spring Data JPA** | Abstraction | Provides `JpaRepository`, query methods |


👉 In short: **JPA is the "what", Hibernate is the "how", and Spring Data JPA is the "helper" that makes the "how" easier.**  


## Cascade in Spring JPA (Exam Notes)

- **Definition**  
  Cascade defines how operations on a parent entity propagate automatically to its child entities.

- **Supported Types**  
  - **PERSIST** → Saving parent also saves children.  
  - **MERGE** → Updating parent also updates children.  
  - **REMOVE** → Deleting parent also deletes children.  
  - **REFRESH** → Reloading parent also reloads children from DB.  
  - **DETACH** → Detaching parent also detaches children.  
  - **ALL** → Includes all of the above.

- **Spring JPA Integration**  
  - Cascade rules are part of the JPA specification.  
  - Spring Data JPA delegates to the JPA provider (usually Hibernate).  
  - Repository methods (`save()`, `delete()`) respect cascade rules automatically.

- **Parent vs Child**  
  - Cascade applies **from parent → child**.  
  - Example: `Department` → `Employee`.  
  - Owning side (foreign key holder) defines cascade behavior.

- **Best Practices**  
  - Use **ALL** only when child lifecycle is tightly bound to parent (e.g., `Order` → `OrderItems`).  
  - Avoid **REMOVE** in loose relationships (e.g., `Department` → `Employee`) to prevent accidental mass deletions.  
  - Always think in terms of **entity lifecycle dependency**.


### Quick Table

| Cascade Type | Direction | Exam Keyword |
|--------------|-----------|--------------|
| **PERSIST** | Parent → Child | Save propagates |
| **MERGE** | Parent → Child | Update propagates |
| **REMOVE** | Parent → Child | Delete propagates |
| **REFRESH** | DB → Entity | Reload propagates |
| **DETACH** | Context → Entity | Detach propagates |
| **ALL** | Includes all | Full lifecycle |
