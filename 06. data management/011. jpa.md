# Java Persistence API
**The JPA Specification (Jakarta Persistence API) is a standard contract that defines how Java objects map to relational database tables, ensuring consistency across different ORM providers like Hibernate. It is not an implementation itself, but a rulebook that frameworks must follow.**  

## Java/Jakarta Persistence API

### Java Persistence API
 - Originally introduced as part of Java EE 5 (2006).
 - Standardized object-relational mapping (ORM) for Java.
 - Defined annotations (@Entity, @Table, @Id) and interfaces (EntityManager, Query).

## Jakarta Persistence API
 - After Oracle donated Java EE to the Eclipse Foundation, the namespace changed from javax.persistence → jakarta.persistence.
 - Functionally the same specification, but under the Jakarta EE umbrella.
 - Current versions evolve under Jakarta branding, ensuring future compatibility and updates.

## What JPA Specification Defines
- **Entity Mapping**  
  - Classes annotated with `@Entity` map to database tables.  
  - Fields/properties map to columns (`@Column`, `@Id`, etc.).  
    ```java
    import jakarta.persistence.Entity;
    import jakarta.persistence.Id;
    import jakarta.persistence.Column;
    
    @Entity
    public class Employee {
    
        @Id
        private Long id;   // Primary Key
    
        @Column(name = "emp_name", nullable = false, length = 100)
        private String name;  // Column with constraints
    
        @Column(unique = true)
        private String email; // Unique column
    
        private double salary; // Default column mapping
    }
    ```
    | Annotation | Purpose |
    | --- | --- |
    | **[@Entity](ca://s?q=JPA_Entity_annotation)** | Declares class as a persistent entity |
    | **[@Table](ca://s?q=JPA_Table_annotation)** | Customize table name/schema |
    | **[@Id](ca://s?q=JPA_Id_annotation)** | Primary key |
    | **[@GeneratedValue](ca://s?q=JPA_GeneratedValue_annotation)** | Auto-generate PK values |
    | **[@Column](ca://s?q=JPA_Column_annotation)** | Customize column mapping |
    | **[@Transient](ca://s?q=JPA_Transient_annotation)** | Excludes field from persistence |

    | Strategy | DB Support | Behavior |
    | --- | --- | --- |
    | **[AUTO](ca://s?q=JPA_GeneratedValue_AUTO)** | Universal | Delegates to provider → dialect decides |
    | **[IDENTITY](ca://s?q=JPA_GeneratedValue_IDENTITY)** | MySQL, SQL Server | Auto‑increment PK |
    | **[SEQUENCE](ca://s?q=JPA_GeneratedValue_SEQUENCE)** | Oracle, PostgreSQL | Uses sequence objects |
    | **[TABLE](ca://s?q=JPA_GeneratedValue_TABLE)** | Any DB | Uses a special table to generate IDs |

- **Relationships**  
  - Rules for `@OneToOne`, `@OneToMany`, `@ManyToMany`, and `@ManyToOne`.  
  - Defines ownership and cascading behaviors.  

- **Persistence Context**  
  - Managed by `EntityManager`.  
  - Ensures identity and lifecycle of entities (persist, merge, remove, detach).  

- **Query Language**  
  - JPQL (Java Persistence Query Language) is part of the spec.  
  - Abstracts SQL into object-oriented queries.  

- **Transactions**  
  - Defines how persistence contexts synchronize with database transactions.  

- **Inheritance Strategies**  
  - Single table, joined, or table-per-class mappings.  


## ⚙️ How It Works in Practice
1. **You write code against JPA interfaces** (`EntityManager`, `Query`).  
2. **Hibernate (or EclipseLink, OpenJPA, etc.) implements those interfaces**.  
3. **Spring Data JPA builds on top of JPA**, simplifying repository creation and query derivation.  


## 📊 Quick Comparison
| Layer | Role | Example |
|-------|------|---------|
| **JPA Specification** | Rulebook | Defines `@Entity`, `EntityManager`, JPQL |
| **Hibernate** | Implementation | Provides ORM engine, SQL generation |
| **Spring Data JPA** | Abstraction | Provides `JpaRepository`, query methods |


👉 In short: **JPA is the "what", Hibernate is the "how", and Spring Data JPA is the "helper" that makes the "how" easier.**
